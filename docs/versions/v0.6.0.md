# v0.6.0 — Constraint & Binding Release

> Organon does one thing excellently: encode constraints and bind them to implementation and tests. Everything else is out of scope.

---

## Vision

v0.6.0 is a two-part release.

**Part 1 — Scope simplification.** Organon removes the process layer: RFC lifecycle, compounding, observations, and workflow authoring. These are valuable practices but they belong to a meta-methodology that teams compose on top of Organon, not inside it. Different teams manage change differently. Organon should not prescribe it.

**Part 2 — Deeper bindings.** With scope sharpened, Organon extends what it *does* own: the binding between organon constraints and the codebase. v0.6.0 adds bidirectional implementation bindings (code claims the organons it implements) and a coverage system (how much of the declared constraint surface is bound).

The result: a smaller, sharper tool with a clearer value proposition and a stronger connection between documentation and code.

---

## What Organon Owns (Post-0.6.0)

### 1. The Organon Files

- **ETHOS.md** — constraints, invariants, principles, decision heuristics
- **PHILOSOPHY.md** — reasoning behind constraints (binds to invariants via `explains_invariants`)
- **PROTOCOL.md** — step-by-step procedures
- **Frontmatter system** — YAML metadata enabling progressive disclosure
- **Scope hierarchy** — product → domain → feature → component inheritance

### 2. Bidirectional Bindings — Two Layers

**Test bindings (pre-existing):**
- `@organon-invariant INV-X-N` annotations in test files
- `invariant-coverage` gate — every non-judgment-call invariant has ≥1 test

**Implementation bindings (new in 0.6.0):**
- `@organon-implements INV-X-N` annotations in source files
- `@organon-implements PROTO-X-N` annotations for protocol implementations
- `@organon-implements domains/billing` scope annotations for domain-level claims
- `implemented_by: [file-paths]` on invariant and protocol frontmatter entries
- Three new coverage gates — domain-binding, implementation-coverage, protocol-coverage

**The complete chain:**
```
ETHOS.md declares INV-BILLING-1
    ↓ implemented_by: [src/billing/InvoiceService.ts]
InvoiceService.ts: @organon-implements INV-BILLING-1
    ↓
InvoiceService.test.ts: @organon-invariant INV-BILLING-1
```

### 3. Domain Lifecycle

Organon as a product design tool — domains exist before code does:

- `status: designing` — spec exists, no implementation expected
- `status: implementing` — development in progress, threshold-based gates apply
- `status: stable` — fully implemented, domain-binding gate enforces 100%

### 4. Structural Verification (10 gates)

1. `frontmatter` — valid YAML, required fields
2. `references` — all paths resolve
3. `domain-binding` — stable domains have ≥1 implementation claim *(new)*
4. `triplets` — invariant declared ↔ test annotated
5. `placeholder-detection` — no uncustomized templates
6. `freshness` — no stale organon files vs code
7. `invariant-coverage` — every testable invariant has ≥1 `@organon-invariant` test
8. `implementation-coverage` — configurable % of invariants have `@organon-implements` claims *(new)*
9. `protocol-coverage` — configurable % of protocols have `@organon-implements` claims *(new)*
10. `version-alignment` — config version matches CLI

## What Leaves Scope

### RFC Process
Change management is not Organon's business. Teams use GitHub issues, ADRs, Jira, Linear — whatever fits their workflow. Organon removes RFC lifecycle, RFC templates, and RFC-specific frontmatter fields.

### Compounding
The COMPOUND phase (reserving session time for methodology improvement) belongs to a meta-methodology layer users compose on top of Organon. Removed from the enforcement loop.

### Workflow & Skill Authoring
Organon no longer specifies how to write Claude skills, Cursor rules, or agent runbooks. The *binding contract* (protocol declares → code implements → test verifies) is Organon's business. The *agent orchestration format* is not.

### Observations System
The observations lifecycle supported compounding. With compounding out of scope, the observations system is removed from the core methodology spec.

## Enforcement Loop

**Before (6 phases):**
```
DEFINE → BIND → EXECUTE → VERIFY → COMPOUND → EVOLVE
```

**After (4 phases):**
```
DEFINE → BIND → EXECUTE → VERIFY
```

- **DEFINE** — Write organon files encoding your constraints
- **BIND** — Annotate code and tests with invariant IDs
- **EXECUTE** — LLMs read organons and work within encoded constraints
- **VERIFY** — `organon verify` checks that bindings hold

## New: Coverage Configuration

```json
{
  "sourceGlobs": ["src/**/*.ts", "src/**/*.js"],
  "sourceIgnorePatterns": ["**/node_modules/**", "**/dist/**"],
  "coverage": {
    "invariantImplementation": 0,
    "protocolImplementation": 0
  }
}
```

Coverage thresholds default to `0` (off until opted in). `domain-binding` is non-configurable — always 100% for `stable` domains.

**Denominator rules:**
- `domain-binding`: all domain + feature scope organons with `status: stable`
- `invariantImplementation`: non-`judgment_call` invariants in domain + feature scope only
- `protocolImplementation`: `semi-automated` + `automated` tier protocols in domain + feature scope only
